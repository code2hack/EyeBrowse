## Product outcome

Run the webpage locally on RG and retain the built-in head pointer and keyboard. Replace the existing Normal/Reading interaction with one browsing surface: the cursor stays visible; reaching the top screen boundary scrolls up, reaching the bottom boundary scrolls down, and moving back inside stops head-driven scrolling. Remove the recenter button. Further outward head movement at any boundary must not accumulate invisible travel that has to be undone before the cursor can return.

Phone EyeBrowse continues its ordinary browsing independently. Online sites still require a working RG network route; a Phone-provided hotspot may supply connectivity without running the Phone EyeBrowse app.

## Approved interaction contract

| Situation/input | Required RG behavior |
| --- | --- |
| Browser visible, including built-in keyboard open | Cursor remains drawn inside the full EyeBrowse screen. There is no Normal/Reading toggle. |
| First valid sensor acquisition on initial launch | Establish an internal pose baseline and start the cursor near screen center automatically. No recenter button, menu item or replacement recenter gesture is needed. |
| Head yaw/pitch with cursor inside boundaries | Move cursor horizontally/vertically; head motion alone does not scroll here. |
| Cursor at top boundary | Scroll the current local webpage upward at a bounded rate while input remains eligible. |
| Cursor at bottom boundary | Scroll the current local webpage downward at a bounded rate while input remains eligible. |
| Cursor remains at top/bottom with head held still | Continue scrolling while sensor data stays fresh; continued outward rotation is not required. |
| First deliberate inward movement | Cursor returns inward without paying back prior outward rotation; edge scrolling stops as it leaves the boundary. |
| Left/right boundary | Clamp horizontal movement. There is no horizontal edge-scroll behavior. Corners use their top/bottom edge for vertical scrolling. |
| Short tap | Activate the current valid local control, page target or keyboard key once. |
| Double tap | No mode transition or other newly assigned action. Keep the existing recognizer's suppression of constituent single-tap activations. |
| Forward/backward pad swipe | No page-scroll action under the literal edge-only rule. The old independent swipe-scroll binding is removed, not retained as a second scrolling trigger. |
| Keyboard show/hide | Cursor bounds still belong to the full RG screen. Only the webpage content rectangle changes; the keyboard's top edge does not become a new screen edge. |
| Unusable sensor, paused/occluded app, document/geometry replacement | Cancel scrolling and pending incompatible input. Keep the cursor drawn as unavailable if the EyeBrowse surface is still visible. Fresh tracking must not replay stale deltas or resume an old edge episode. |

“Screen edge” means the top/bottom limit of the measured full EyeBrowse drawable screen, respecting actual system insets and the cursor glyph's size so the glyph remains visible. It is not the edge of the reduced webpage rectangle or a broad near-edge hot zone. Edge membership derives from the clamped displayed cursor state, with only documented subpixel/pixel-rounding treatment. Looking farther upward/downward is not an alternative scroll trigger.

This rule controls pointer/gesture-originated scrolling. Required browser field-reveal behavior, ordinary page-authored scrolling, and explicit page controls are not misclassified as violations of the pointer rule. Programmatic layout changes do not manufacture a fresh user edge-entry event.

### Margin-bug acceptance example

Move the cursor to the right edge, continue turning farther right, then reverse slightly left. The cursor must begin moving left after that first valid inward input, without undoing the accumulated outward angle. Apply the same check to all four edges, multiple overshoot amounts/durations, corners, and top/bottom scrolling. Equal inward input must give equivalent return response regardless of prior outward travel.

The inspected `HeadPointerModel` already clamps both target and displayed normalized coordinates. Its target remains derived from a fixed pose reference, however, so continued rotation beyond a saturated edge can require angle payback. This is a source-supported explanation of the Owner's report, not a device reproduction performed while drafting. The Worker must retain a failing regression against the actual old model and qualify the correction.

### Approved initial engineering parameters

These were proposed in R3 and are published unchanged with its approval; they are not claims about wearer comfort:

- Initial constant edge-scroll rate: **240 native viewport pixels/second**. Keep tuning in one settings object; do not derive speed from hidden out-of-bounds head rotation.
- Fresh-sample-to-visible-cursor and edge-entry/exit reaction: **at most 100 ms** in the predeclared device/replay checks. Ordinary declared noise filtering still applies; compare reversal latency independently of overshoot amount.
- Sensor stale cutoff: retain **250 ms** initially. Every scroll tick checks source age and current authority before applying an effect, even if a timeout callback is delayed.
- A scroll integration step represents at most **50 ms**; do not replay elapsed movement after a scheduling stall.
- Confirmed tap/key-to-local-operation dispatch: retain the existing **100 ms** boundary. Report recognition time, editor completion and rendered effects separately.

A timestamped production-input replay is appropriate functional evidence; it does not establish worn head-motion ergonomics. Keep speed/units, sample traces, native scroll positions and clocks explicit.
