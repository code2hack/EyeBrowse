## 1. Authorized outcome

RG-only incremental update: double default pointing, bounded off-screen vertical scroll strips, numeric arrow controls instead of presets, fix real QR recognition problems, and bundle Mihomo for automatic app-local routing with multiple independently enabled profiles. Mainland China/local/private/tailnet traffic is DIRECT; other traffic uses the healthy lowest-delay node across all enabled sources; no usable candidate means DIRECT.

Keep the existing 480-wide × 640-high portrait black HUD and all eight toolbar actions, star inside the short address slot, tabs, bookmarks, built-in keyboard, native current-focus input and accepted temporary native password echo. Phone code, proxy installation, version metadata and mandatory physical Phone tests are not part of this version. This is not a new architecture fork or an opportunity to revive local stale-input frameworks.

The Owner requested all six issues and SPEC changes be published and explicitly required the separate v0.0.3 branch. D1 numeric/import defaults become the initial implementation values in D3.1/H3.1, not an assertion that the Owner separately chose each number. The unchanged HUD design is not reopened for approval. Use native-size implementation checks for the changed UI, not a new whole-project image/approval gate.

## 2. Fixed initial implementation values

| Parameter | Value |
| --- | --- |
| Pointer numeric scale | 0.1×–6.0×, step 0.1×, default 2.0× relative to old Standard on both axes |
| One-time pointer migration | Low→1.5×, Standard→2.0×, High→2.5×; no repeated doubling |
| Scroll numeric speed | 10–1,200 native viewport px/s, step 10, default 240; preserve old 120/240/360 choices |
| Virtual top/bottom strips | 24 rendered pixels each, outside the full screen; hidden pointer still tracks |
| Pointer/scroll behavior | Stop when returning to the visible screen, not on the first small inward movement still outside; outer-limit excess discarded |
| Subscription refresh | Every 30 minutes / 1,800 s, including saved OFF profiles |
| Enabled-node tests | On pool change and every 5 min while active, using core facilities |
| Regional rule-data refresh | Every 24 h with bundled initial/last-good data |
| New profile | ON by default; same source update preserves name/toggle; different URL adds a row |
| Import formats | HTTP(S) source with Clash/Mihomo YAML usable proxies list; conventional clash install-config URL wrapper; no unsupported-format silent success |

Numeric Settings is `label [←] value [→]`, single step per tap, immediately effective and persisted, arrow disabled at limits. Proxy is only profile name + independent toggle + Delete, followed by Add a new profile; no diagnostics dashboard. More → QR scan is the website flow; Settings → Proxy → Add is the subscription flow. Both use the same camera/decoder.

## 4. Work boundaries and minimal engineering

V3-01 reuses HeadPointerModel/PointerOverlay/EdgeScrollMotion/LocalInputSettings and native Settings, changes gain/bounds rather than a new pointer framework. Visible bounds are distinct from logical off-screen strips; no off-screen click can turn into an on-screen action. Preserve left/right clamping, current horizontal tab swipes and ordinary sensor/Activity lifecycle.

V3-02 begins with current CameraX/ZXing implementation and actual analyzer frames. Identify the failed stage rather than assume camera invocation. Valid test photos and decoder tests support but cannot replace real optical acquisition. Include short and long dummy subscription QR payloads, repeated use and cleanup; no Phone prerequisite.

V3-03 proves a complete request through a pinned core on actual RG using owned test nodes/configuration before the production importer exists. Verify WebView proxy feature support, ABI/binding/provenance/redistribution compatibility and relevant native HTTP routing. Kotlin remains first-party language; use the standing unmodified-vendor/generated exception, not an unannounced first-party Go/native bridge. Report a genuine missing binding or public API before expanding scope.

EyeBrowse owns one Rule configuration: private/local/tailnet and mainland-China domain/IP data DIRECT, other destinations shared AUTO with DIRECT only as fallback. Profiles supply nodes, never imported global rules/DNS/controller/scripts. A successful empty-group fallback is not proof of all-unhealthy fallback. DIRECT cannot win a normal latency contest against healthy proxy nodes. Use native core health/selection; minimal status integration is allowed, not a second benchmark engine.

V3-04 supplies real import instead of V3-03 test seeding. User toggles include each source independently; names may collide across providers but runtime node identity must not. Different source URL is not silently replacement by hostname; validation precedes cached-data replacement. No per-profile winning selection. UI is minimal and does not expose URLs/tokens.

V3-05 coordinates one refresh owner and normal Android scheduling, including OFF source refresh and overdue launch handling. No exact-alarm/permanent timer service, duplicate core/app update loops or promised execution while Android force-stops the app. Failed source/rule downloads keep last-good data. Changes affect new connections without forced tab reload.

H3.1 maps ten HUD checks (H3-C01…C10) across toolbar, Settings, strips, profile list, scanners, keyboard, black output, routing and lifecycle. V3-06 verifies them together; simulated layout pictures are not production proof.

Starting host command: `./gradlew :app-rg:testDebugUnitTest :app-rg:assembleDebug :app-rg:assembleDebugAndroidTest :app-rg:lintDebug`, using current DEV/toolchain and affected shared checks only as needed. Prefer existing high-level seams. Use owned endpoints/test subscriptions and actual native input/optical QR evidence, not huge mock networks or local-input identity tests.
