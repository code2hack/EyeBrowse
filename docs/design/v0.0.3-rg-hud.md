## 1. Authority and continuity

This document is the complete current RG HUD contract. Keep the Owner-approved v0.0.2 toolbar, portrait geometry, typography, black palette and native input. Replace preset Settings with numeric steppers, add the minimal Proxy profile list/dedicated importer, and permit intentional cursor invisibility in bounded vertical strips. Old H1.2 on-screen-only and preset-only clauses are historical, not concurrent requirements.

The Owner requested publication of the presented v0.0.3 plan/issues and SPEC. The changed-layout coordinates below implement those designs within the already approved canvas. Numeric values use the published D1 completion defaults. No additional whole-HUD review, illustration generation, ticket-plan or approach-preapproval gate is introduced. Workers must implement these controls, not silently redesign or omit them. Actual screenshots/layout/interaction checks remain necessary for implementation acceptance.

This is a browser UI contract, not a local event-fencing protocol. Use direct Android View/WebView taps, native focus and normal lifecycle. The prior accepted native temporary password-character echo remains accepted. No custom masking, editor replacement or ABA/queued-key framework.

## 3. Exact persistent toolbar — all eight actions

One row, never wrapped:

`[ × ][ ← ][ → ][ ↻ ][ short address … ☆ ][ i/n ][ ⋮ ]`

| Target | X interval | Meaning |
| --- | --- | --- |
| `hud.close_tab` | [0,48) | Close selected tab |
| `hud.back` | [48,96) | Selected WebView Back |
| `hud.forward` | [96,144) | Selected WebView Forward |
| `hud.refresh` | [144,192) | Reload |
| `hud.address_slot` | [192,368) | Compact address plus its dedicated trailing star |
| `hud.address` child | [192,320) | Short display / full horizontally editable URL |
| `hud.bookmark` child | [320,368) | Independent `☆/★` bookmark target |
| `hud.tab_counter` | [368,432) | Actual one-based `i/n` |
| `hud.more` | [432,480) | Three-dot More |

Seven top-level slots, **eight independent actions**. The star is always inside the trailing address slot, independently clickable and fixed while editing. It bookmarks the committed page, not the unsent draft. Long domains/URLs cannot displace the star, counter, Forward, Refresh or More. Back/Forward/Refresh remain visible when unavailable, with dim/non-actionable state. Empty page shows a disabled outline star rather than removing its target.

Tab counter opens the tab list. Add selects a new appended empty tab/address entry; first/last swipes do not wrap. Close chooses the next remaining slot or previous last; sole-tab close leaves empty `1/1`. Right pad swipe = next tab; left = previous. No vertical scroll/history/click side effect. A recognized double tap does nothing and suppresses constituent activations. No recenter control or Normal/Reading toggle.

More rectangle `(256,48,224,192)` has exactly four 48-px rows: **Add new tab, Bookmarks, QR scan, Settings**. Proxy is NOT a fifth menu item. An outside menu tap dismisses without clicking through; Android Back and appropriate local exits dismiss utilities. Browser toolbar controls keep their browser meanings. Stop covered-page edge scrolling with ordinary UI lifecycle.

## 6. Proxy — profile list only

Settings → Proxy shows one content heading and rows:

```text
Proxy

Profile 1                       [ ON  ] [ Delete ]
Profile 2                       [ ON  ] [ Delete ]
Profile 3                       [ OFF ] [ Delete ]

Add a new profile
```

Keep the same top toolbar. Heading/ordinary return use the Settings content treatment. List begins at y=112; use 64-px row pitch and 56-px hit-row height. In each row: name x=[16,280), toggle x=[288,352), Delete x=[360,464). Long names elide within their area. Toggle and Delete have separate at-least-48-px-high targets. Following the rows, **Add a new profile** is a `(x=16,width=448,height=48)` action in the same scrollable content, not fixed bottom navigation. Empty state still offers Add. Long lists scroll using the top/bottom virtual strips; the hidden browser page must not scroll.

ON/OFF is a separate switch per profile, **not a radio selection**. Multiple profiles may be ON. ON adds that source's nodes to the shared pool; OFF excludes them from new selection but retains saved data; Delete removes that source. Each of these must have real storage/core effect, not only a local visual toggle. Delete is not a switch to another selected profile. Do not force-reload tabs to change the pool.

This page contains no node information, latency, traffic counts, core version, update timestamps, manual node selection, mode editor or per-profile detail dashboard. Brief importing/error/success feedback and ordinary return/cancel controls are allowed to make operations understandable. Never display raw credential-bearing subscription URLs as profile names.

## 7. Distinct QR entry flows

| Entry | Behavior |
| --- | --- |
| More → QR scan | Web address scanner; decoded preview → **Open / Cancel**; Open navigates selected tab. |
| Settings → Proxy → Add a new profile | Subscription scanner; decode supported source URL → fetch/validate → automatically add/update → return to profile list. |

Both reuse the same real camera/analyzer/decoder. Show a clear scanner-purpose heading and Cancel, black surrounding UI with camera preview as media. Permission denied, camera unavailable, no-code-yet, unsupported data, download/validation failure and normal cancellation have usable exits. No extra automatic classification between web and subscription purposes is required.

New valid subscription is ON. Same source address updates one row and preserves its name/toggle; different address adds a row. Failed imports preserve working data. Profile import does not navigate the page and website scanning does not import subscriptions. Supported forms and data extraction follow SPEC §7; malicious/imported fields cannot change app routing, controller or OS configuration. Cancel/exit stops camera activity through normal lifecycle.

## 8. Pointer strips and state transitions

The logical pointer may move within **24 rendered pixels above/below** the full screen. At 480×640: upper `[-24,0)`, visible `[0,640)`, lower `[640,664]`. Draw the cursor only in the visible interval; at transition its glyph may briefly clip. Hide it in a strip without treating that as lost tracking. Left/right remain bounded on-screen. Off-screen taps do nothing; normal horizontal pad tab switching retains its behavior.

Scrolling starts on entry into a strip, continues while still in it (including small inward motion), and stops when the pointer re-enters the visible screen. Clamp at the outer strip edge and discard further angular/filter travel. Padding is invisible logical space, never a visible band, additional bezel, or page-size reduction. Keyboard/page and toolbar/page boundaries are not triggers.

| Event/state | Visible result and ordinary handling |
| --- | --- |
| Launch / usable tracking | Current local browser; cursor initializes automatically; saved numeric settings apply once. |
| Pointer crosses top/bottom screen boundary | Cursor disappears; currently visible page/list scrolls in that direction. |
| Small inward movement but pointer remains in strip | Cursor remains hidden; scroll continues. |
| Pointer returns into visible screen | Cursor reappears immediately; head-triggered scroll stops. |
| Further outward movement at outer strip limit | No additional stored travel; return distance stays bounded by strip depth. |
| Off-screen tap | No click/key/delete action; do not clamp to an on-screen target. |
| Tracking unavailable / Activity paused | Stop motion/scroll normally; distinguish lost tracking from purposeful strip hiding. |
| Keyboard shown / hidden | Page reflows without losing text; full-screen strip boundaries do not move. |
| Tab swipe/selection | Visible tab changes using native focus; previous active scroll stops. |
| Open Settings / Proxy | Black utility content below same toolbar; page input is covered. |
| Decrease/increase setting | One numeric step, immediate effect/save; endpoint arrows dim. |
| Profile toggle | Only that saved profile's node contribution changes; other toggles unchanged. |
| Delete profile | Row/source removed; candidates recomputed; no sources/all unhealthy uses DIRECT. |
| Add-profile scan succeeds | New enabled row or same-source update; no browser navigation. |
| Subscription update fails | Last good row/data remain; no automatic toggle reset or fake successful replacement. |
| Proxy candidates absent/recover | Subsequent connections DIRECT / return to automatic pool; no forced tab reload. |
| Ordinary web QR result | Preview, then deliberate Open or Cancel. |
| More/utility exit | Return through normal local UI; no second browsing mode or input-generation framework. |

For a visible scrollable utility, strip scrolling belongs to its own list. Stop callbacks when not active/visible or tracking expires. Use current View coordinates, native focus and normal lifecycle, not a custom stale-hit or queued-key protocol.
